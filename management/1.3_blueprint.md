## 1. ARQUITECTURA DE DATOS Y ENTIDADES (SQL)

* **Base de Datos Seleccionada:** PostgreSQL en Supabase
  * **Justificación:** Integración nativa con la autenticación (Google OAuth), soporte de Row Level Security (RLS) para proteger los datos a nivel de fila, y WebSockets integrados para la sincronización y notificaciones futuras.
  * **Estándar:** `snake_case` estricto e inmutable en todas las capas.

### Relaciones y Propósito
* **`profiles`:** Información pública del usuario vinculada a `auth.users`. Extendida con el nivel de suscripción (`subscription_tier`) para el modelo Freemium.
* **`groups`:** Espacios de trabajo grupales/familiares.
* **`group_members`:** Resuelve la relación N:M entre usuarios y grupos. Contiene el rol (`admin`, `member`), el alias local (`group_nickname`) y el aporte de ingresos (`monthly_income`).
* **`categories`:** Clasificación de consumos (globales o personalizadas).
* **`payment_methods`:** Medios de pago (ej. Efectivo, Tarjeta, Yape).
* **`merchants`:** Establecimientos comerciales (RUC/Nombre) para evitar duplicación de texto.
* **`transactions`:** Registro central. Si `group_id IS NULL`, es privado. Si está asignado, es grupal.
* **`invitations`:** Gestión del flujo híbrido de invitaciones por correo electrónico.

## 2. FLUJO LÓGICO Y ENDPOINTS DE API

* **Flujo Híbrido de Invitaciones:** 
  1. El administrador ingresa un correo. Si existe, notifica in-app. Si no existe, se guarda pendiente.
  2. Un Trigger (`handle_new_user_invitation`) vincula automáticamente las invitaciones pendientes cuando el usuario se registra con Google.
* **Límites Freemium (Gating):** 
  Controlado estrictamente por Triggers en PostgreSQL (ej. máximo 2 grupos o 5 miembros si `subscription_tier = 'free'`).
* **Sincronización Offline:** 
  Motor diferencial. La app móvil escribe en SQLite (`sync_status = 'created'`). En background, sube los deltas a Supabase RPCs o REST y actualiza `local_updated_at`.

## 3. STACK TECNOLÓGICO Y ENTORNO DE DESARROLLO

* **Tecnologías Core:**
  * **Backend:** Supabase (Auth, Postgres, Storage).
  * **Frontend Mobile:** React Native.
  * **Lenguaje:** **TypeScript (Estricto por defecto)** para seguridad de tipos de extremo a extremo.

### Mapeo de Entorno y Flujo de Trabajo (Workflow)

1. **App Móvil (Android):**
   * **Framework:** Expo (Development Build / Expo Go).
   * **Navegación:** Expo Router (Basado en sistema de archivos).
   * **UI / Estilos:** React Native Paper (Material Design para velocidad MVP).
   * **Base de Datos Local:** `expo-sqlite`.
   * **Estado Global:** Zustand (ligero, según necesidad).
   * **Monetización y Ads:** `react-native-iap` / `revenuecat` (pagos) y `react-native-google-mobile-ads` (anuncios condicionados por `subscription_tier`).

## 4. MANEJO DE CASOS CRÍTICOS Y SEGURIDAD

* **Pérdida de Conectividad (Red):** Patrón *Offline-First*. Escritura inmediata local en SQLite. Sincronización en segundo plano con Supabase al recuperar red.
* **Políticas de Seguridad (Supabase RLS):**
  * Perfiles editables solo por su dueño.
  * Grupos, transacciones y storage accesibles/editables solo por miembros validados en `group_members`.
  * Privacidad absoluta para transacciones individuales (`group_id IS NULL`).
